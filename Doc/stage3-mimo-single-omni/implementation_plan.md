# 执行计划

制定时间：2026-10-25。阶段状态仅由选定 `task_plan.md` 维护。
本轮交付 Phase 1；以下实现是计划，不是已运行的功能。

## Phase 1: 架构恢复与计划

方案：恢复已有任务、核对 Git、阅读历史 Doc，追踪 Qwen/MiMo/TTS 代码和测试，
建立当前知识库、决策表、失败日志及新会话入口。

产物：计划三文件、AGENTS.md、当前知识库。外部 Doc 仅新增发布。
门槛：可明确现有能力、依赖、未验证项和下一步；检查文档路径、Git 差异及记录完整性。

## Phase 2: 环境、基线与 TTS 可行性

2026-10-25 第二阶段启动修订：用户要求直接进行 GPU 验证，不以 CPU 回归为前置。
先 source 用户 env.sh，再激活 omni；按进程固定当前子模块 PYTHONPATH，
不重装旧环境。以下原始顺序作为 Phase 1 制定记录保留，以本修订为准。

顺序：先环境和 CPU，再独立 TTS，最后补当前 MiMo 必需差异验收。
不重复历史 TP4/TP8 性能实验；只有源码路径/模型能力或新环境发生变化才跑针对性 smoke。

方案：

1. 记录父/子库 SHA、Python、包版本、真实导入路径、GPU/端口与现有进程归属。
   优先复用匹配二进制，但不重装仍在服务的 omni 环境。
2. 运行相关 duplex、VAD、splitter、TTS CPU 测试，保存基线失败与缺依赖。
3. 新建独立 TTS deploy 配置和 run 目录；验证 CustomVoice task、语言、音色、
   PCM 输出格式、首包/尾包、短句和长句。
4. 验证 HTTP 流关闭在等待首包/出音频/尾包阶段的取消，以及取消后新请求正常。
5. 当前 MiMo 验证原始音频输入和正文 SSE；检查自动架构转换、thinking/content 分离。

产物：环境清单、不可覆盖的 run manifest、独立 TTS 配置、smoke 报告和取消时序。
门槛：音频内容核对通过、24 kHz PCM 正确、终态无残留请求；
取消失败必须先修窄范围后端生命周期，不允许靠丢包宣称通过。
具体耗时阈值根据本机基线制定，不能先借用旧实验数字。

## Phase 3: 独立 TTS 适配与会话边界证明

方案：

1. 在父仓库新增项目包、相关测试及可配置入口；目录名实现时决定，
   不为计划先造空框架。先 mock 验证 DuplexStagePort 与现有 runner 的组合。
2. 外部 TTS 适配器接收 segment_id、正文区间、音色/语言/样式及取消令牌，
   返回有序 PCM chunk、sample rate、段终态和错误。
3. 复用 SpeechTextSplitter；保留原正文区间，显式处理尾部 flush、无标点长文、
   空段、数字/缩写、控制内容及最大输入限制，不逐 chunk 重读全部前文。
4. 默认一条有序合成消费任务，输入/正文接收独立；预算以字符/段数/音频时长计，
   不止限制 Python queue 项数。达到预算明确背压或取消，不静默丢文本。
5. 验证每次 await 后 fence、取消幂等、迟到 chunk、服务错误和 request_id 生命周期。

决策门：能组合就复用现有会话/播放账本；不能组合时记录具体契约缺口，
只扩展必要 fork 接口，不机械迁移 session 代码。

产物：TTS 适配器、mock 协议证明、分段/有界队列单元测试。
门槛：同一正文分段无重复漏读，队列有界，取消后旧包不可发出，
TTS 错误不是正常 EOS，旧 Qwen 路径测试不回归。

## Phase 4: MiMo 音频输入与正文到语音

方案：

1. 提取/复用窄 MiMo SSE 客户端与原始输入转换，不携带 Qwen prefill 或 embedding。
2. 新增 MiMo duplex 插件/外部服务端口组合；单一历史快照由现有会话账本提供。
   系统指令、裁剪、音频采样/格式转换明确归属，视频能力不顺带扩展。
3. MiMo delta.content 一路投影 transcript，一路送稳定分段；不朗读 reasoning/tool/control。
   先实现手动 commit，便于与 VAD 解耦验证。
4. 仅在全部正文处理、已提交段结束/失败后结束回复；
   不把 MiMo SSE DONE 当成最后音频或用户播放完成。
5. 输出采样率和 response_id 保持现有协议预期；复用 realtime_web，
   如需新的 profile，仅加必要模型名/配置/ACK 映射。

产物：文本/原始音频输入到正文/语音输出的单轮服务、配置和回放测试。
门槛：进程与请求图无 Qwen3-Omni 理解/语音 stage，历史不依赖其 tokenizer；
中英数字混合内容匹配，受控慢 SSE 下首个有效音频早于 MiMo DONE；
取消、空正文、异常断流和新会话隔离均通过。
明确记录句间重新合成，不声称整个回复只有一条 TTS KV。

## Phase 5: 声学/语义状态机、真双工与播放历史

拆成三个独立子门槛，每完成一个追加记录：

### 5A 声学策略

独立输入/输出状态与纯 reducer；语音开始、候选结束、继续说话、
明确 commit/cancel、超时和输出状态是事件，不在音频接收任务内等待模型。
首版显式 acoustic 模式，不更改旧 server_vad 的语义。

门槛：假时钟回放稳定，噪声/短音/句中停顿不重复 commit，
生成/播放期间麦克风输入持续被接收和处理。

### 5B 语义决策

定义 continue/wait/complete/backchannel/interrupt 及置信度/超时契约。
用同一 MiMo 的有限窗口音频判断做候选实验，不额外引入第二个理解模型。
结果绑定 input_revision/fence；新音频到达后旧结果作废。
先建立标注样例，对照声学基线，再确认推理成本及是否启用。

门槛：附和、真实抢话、未完句和回声样例分别量化；错误/超时按显式配置降级，
不得把声学启发式记录为语义 VAD 已完成。

### 5C 取消与已播放历史

fence 先失效；清理浏览器播放、待合成文本、MiMo SSE、TTS HTTP 与其实际 engine 请求。
保留正在抢话的用户音频，不让旧轮清理删除新输入。
只提交 ACK 确认的完整分段；段内部分播放不虚构对齐。
重现旧问题：多次打断、已听前段、未听尾段、新问题不应重答已确认回答。

门槛：取消等待首字/首音频/播放/尾包各时点，迟到 ACK/语义结果/文本/音频均隔离；
真后端请求终止且下一轮成功；部分历史结果可解释且通过回放断言。

## Phase 6: 回归、性能与交付

方案：跑相关 CPU 全套、真实浏览器麦克风/VAD/播放 ACK、故障注入和长会话回放。
覆盖断线恢复/关闭/reset、并发资源隔离、MiMo/TTS 失败、背压、重复/乱序 ACK。
保留 Qwen-only、MiMo-Qwen 的受影响回归；不重跑不相关的全模型 suite。

度量：

- speech end -> commit、MiMo TTFT、首段 ready、TTS TTFA、首播放延迟。
- MiMo DONE 与首有效音频相对时间，句间 gap/underrun、TTS RTF。
- 候选/确认抢话 -> 播放停止，与后端取消完成分开统计。
- p50/p95、GPU 峰值显存、队列最大时长、残留请求/任务、长会话历史增长。
- 语义端点/抢话准确率、误打断率、额外推理时间。

门槛：本机约定指标与功能矩阵均满足；人工听测或独立 ASR 内容确认，
不能只用非空 WAV/health 判定成功。
交付：运行说明、最终设计决策、失败及解决记录、版本/配置/测试报告、
独立实验目录索引和新增外部知识快照。提交/推送按用户当前要求执行。
